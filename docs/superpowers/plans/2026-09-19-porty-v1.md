# Porty v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Build the complete Porty v1 single-server Docker Compose and Git manager.

**Architecture:** A Go modular monolith owns domain/application behavior and explicit infrastructure adapters. A Preact/Vite UI is embedded in the binary; SQLite persists metadata while stack files remain in one Git worktree.

**Tech Stack:** Go 1.27.1, net/http, modernc SQLite, Argon2id, coder/websocket, Preact, TypeScript, Vite, CodeMirror 6.

**Spec:** `docs/superpowers/specs/2026-09-19-porty-design.md`

## Global Constraints

- Linux only; one administrator; one repository and branch.
- Exact stack marker is `docker-compose.yml` in an immediate child directory.
- No shell command construction and no arbitrary filesystem paths after setup.
- Tests precede production code and every task ends with the whole available suite green.
- Docker is unavailable in the current environment; Docker behavior requires command-contract/fake-process tests, with live smoke testing left as an explicit environment gate.

## Review Focus

- Traversal, symlink, special-file, and stale-write inputs must fail without touching outside files.
- Adopted Git repositories with hooks or command-bearing configuration must be rejected or neutralized.
- Secrets must not appear in API responses, structured logs, operation output, or persisted rendered Compose content.
- Repository/stack lock ordering must not deadlock under pull/edit/deploy races.
- Process crash, stream disconnect, slow consumer, and timeout behavior must terminate or preserve the correct operation.
